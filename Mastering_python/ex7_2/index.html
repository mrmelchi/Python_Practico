Ejercicio 7.2

Objetivos:

  • Encadenamiento de decoradores
  • Definición de decoradores que aceptan argumentos.

Archivos modificados: logcall.py, validate.py

(a) Copia de metadatos

Cuando un decorador encapsula una función, a menudo se pierde información sobre el nombre de la función, las cadenas de documentación y otros detalles. Verifica esto:

>>> @logged
    def add(x,y):
        'Adiciona dos elementos'
        return x+y

>>> add
<function wrapper at 0x4439b0>
>>> help(add)
... observa la salida...
>>>

Corrige la definición del decorador logged para que copie los metadatos de la función correctamente. Para ello, usa el decorador @wraps(func) como se muestra en las notas.

Una vez que hayas terminado, asegúrate de que el decorador conserve el nombre de la función y la cadena de documentación.

>>> @logged
    def add(x,y):
        'Adiciona dos elementos'
        return x+y

>>> add
<function add at 0x4439b0>
>>> add.__doc__
'Adiciona dos elementos'
>>>

Corrige el decorador @validated que escribiste anteriormente para que también conserve los metadatos usando @wraps(func).

(b) Tu primer decorador con argumentos

El decorador @logged que definiste anteriormente siempre imprime un mensaje simple con el nombre de la función. Supón que quieres que el usuario pueda especificar un mensaje personalizado.

Define un nuevo decorador @logformat(fmt) que acepte una cadena de formato como argumento y use fmt.format(func=func) para formatear una función proporcionada en un mensaje de registro:

# sample.py
...
from logcall import logformat

@logformat('{func.__code__.co_filename}:{func.__name__}')
def mul(x,y):
    return x*y

Para ello, necesitas definir un decorador que acepte un argumento. Así debería verse al probarlo:

>>> import sample
Añadiendo logging a `add`
Añadiendo logging a `sub`
Añadiendo logging a `mul`
>>> sample.add(2,3)
Añadiendo logging a `add`
5
>>> sample.mul(2,3)
sample.py:mul
6
>>>

Para simplificar aún más el código, muestra cómo definir el decorador @logged original usando el decorador @logformat.

(c) Múltiples decoradores y métodos

La situación puede complicarse al aplicar decoradores a los métodos de una clase. Intenta aplicar tu decorador @logged a los métodos de la siguiente clase.

class Spam:
    @logged
    def instance_method(self):
        pass

    @logged
    @classmethod
    def class_method(cls):
        pass

    @logged
    @staticmethod
    def static_method():
        pass

    @logged
    @property
    def property_method(self):
        pass

¿Funciona? (Pista: no). ¿Hay alguna forma de corregir el código para que funcione? Por ejemplo, ¿puedes hacer que el siguiente ejemplo funcione?

>>> s = Spam()
>>> s.instance_method()
instance_method
>>> Spam.class_method()
class_method
>>> Spam.static_method()
static_method
>>> s.property_method
property_method
>>>

(d) Validación (Traído de nuevo)

En el último ejercicio, escribiste un decorador @validated que aplicaba anotaciones de tipo. Por ejemplo:

@validated
def add(x: Integer, y:Integer) -> Integer:
    return x + y

Crea un nuevo decorador @enforce() que aplique los tipos especificados mediante argumentos de palabra clave al decorador. Por ejemplo:

@enforce(x=Integer, y=Integer, return_=Integer)
def add(x, y):
    return x + y

El comportamiento resultante de la función decorada debería ser idéntico. Nota: La palabra clave return_ especifica el tipo de retorno. return es una palabra reservada de Python, por lo que debe elegir un nombre ligeramente diferente.

Discusión

Escribir decoradores robustos suele ser mucho más difícil de lo que parece. Lectura recomendada: De la manera que implementaste tu decorador de Python es incorrecto
