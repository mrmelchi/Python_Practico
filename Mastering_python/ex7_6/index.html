(a) La última frontera

En el Ejercicio 7.3, permitimos definir estructuras con verificación de tipos de la siguiente manera:

from validate import String, PositiveInteger, PositiveFloat
from structure import Structure

class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares: PositiveInteger):
        self.shares -= nshares

Hay muchas Hay cosas que suceden en segundo plano. Sin embargo, una molestia se refiere a todas esas importaciones de nombres de tipo en la parte superior (p. ej., String, PositiveInteger, etc.). Este tipo de cosas podrían llevar a una sentencia from validate import *. Un aspecto interesante de una metaclase es que puede usarse para controlar el proceso de definición de una clase. Esto incluye la gestión del entorno de la propia definición de clase. Abordemos estas importaciones.

El primer paso para gestionar todos los nombres de validadores es recopilarlos. Vaya al archivo validate.py y modifique la clase base Validator con este fragmento de código adicional que incluye __init_subclass__() de nuevo:

# validate.py

class Validator:
    ...

    # Collect all derived classes into a dict
    validators = { }
    @classmethod
    def __init_subclass__(cls):
        cls.validators[cls.__name__] = cls

No es mucho, pero está creando un pequeño espacio de nombres para todas las subclases de Validator. Échale un vistazo:

>>> from validate import Validator
>>> Validator.validators
{'Float': <class 'validate.Float'>,
 'Integer': <class 'validate.Integer'>,
 'NonEmpty': <class 'validate.NonEmpty'>,
 'NonEmptyString': <class 'validate.NonEmptyString'>,
 'Positive': <class 'validate.Positive'>,
 'PositiveFloat': <class 'validate.PositiveFloat'>,
 'PositiveInteger': <class 'validate.PositiveInteger'>,
 'String': <class 'validate.String'>,
 'Typed': <class 'validate.Typed'>}
>>>

Ahora que Una vez hecho esto, inyectemos este espacio de nombres en el espacio de nombres de las clases definidas desde Structure. Defina la siguiente metaclase:

# structure.py
...

from validate import Validator
from collections import ChainMap

class StructureMeta(type):
    @classmethod
    def __prepare__(meta, clsname, bases):
        return ChainMap({}, Validator.validators)

    @staticmethod
    def __new__(meta, name, bases, methods):
        methods = methods.maps[0]
        return super().__new__(meta, name, bases, methods)

class Structure(metaclass=StructureMeta):
    ...

En este código, el método __prepare__() crea una asignación especial de ChainMap que consta de un diccionario vacío y un diccionario con todos los validadores definidos. El diccionario vacío que aparece primero recopilará todas las definiciones realizadas dentro del cuerpo de la clase. El diccionario Validator.validators pondrá a disposición todas las definiciones de tipo para usarlas como descriptores o anotaciones de tipo de argumento.

El método __new__() descarta el resto del diccionario de validadores y pasa las definiciones restantes al constructor de tipos. Es ingenioso, pero permite eliminar las molestas importaciones:

# stock.py

from structure import Structure

class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares: PositiveInteger):
        self.shares -= nshares
