Ejercicio 4.4

Objetivos:

  • Aprender a personalizar el acceso a atributos
  • Delegación vs. herencia

(a) Slots vs. setattr

En ejercicios anteriores, se utilizó __slots__ para enumerar los atributos de instancia en una clase. El propósito principal de slots es optimizar el uso de memoria. Un efecto secundario es que limita estrictamente los atributos permitidos a aquellos enumerados. Una desventaja de slots es que a menudo interactúa de manera extraña con otras partes de Python (por ejemplo, las clases que usan slots no se pueden usar con herencia múltiple). Por esa razón, realmente no debería usar slots excepto en casos especiales.

Si realmente quisieras limitar el conjunto de atributos permitidos, una forma alternativa de hacerlo sería definir un método __setattr__(). Pruebe este experimento:

>>> class Stock:
        def __init__(self, name, shares, price):
            self.name = name
            self.shares = shares
            self.price = price
        def __setattr__(self, name, value):
            if name not in { 'name', 'shares', 'price' }:
                raise AttributeError('No attribute %s' % name)
            super().__setattr__(name, value)

>>> s = Stock('GOOG', 100, 490.1)
>>> s.name
'GOOG'
>>> s.shares = 75
>>> s.share = 50
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 8, in __setattr__
AttributeError: No attribute share
>>>

En este ejemplo, no hay ranuras, pero el método __setattr__() aún restringe los atributos a aquellos en un conjunto predefinido. Probablemente deba pensar en cómo este enfoque podría interactuar con la herencia (por ejemplo, si las subclases quisieran agregar nuevos atributos, probablemente necesitarían redefinir __setattr__() para que funcione).

(b) Proxies

Una clase proxy es una clase que envuelve a una clase existente y proporciona una interfaz similar. Defina la siguiente clase que crea una capa de solo lectura alrededor de un objeto existente:

>>> class Readonly:
def __init__(self, obj):
self.__dict__['_obj'] = obj
def __setattr__(self, name, value):
raise AttributeError("Can't set attribute")
def __getattr__(self, name):
return getattr(self._obj, name)

>>>

Para usar la clase, simplemente la envuelve alrededor de una instancia existente:

>>> from stock import Stock
>>> s = Stock('GOOG', 100, 490.1)
>>> p = Readonly(s)
>>> p.name
'GOOG'
>>> p.shares
100
>>> p.cost
49010.0
>>> p.shares = 50
Traceback (última llamada más reciente):
Archivo "<stdin>", línea 1, en <module>
Archivo "<stdin>", línea 8, en __setattr__
AttributeError: Can't set attribute
>>>

(c) Delegación como alternativa a la herencia

La delegación se utiliza a veces como una alternativa a la herencia. La idea es casi la misma que la de la clase proxy que definió en la parte (b). Intente definir la siguiente clase:

>>> class Spam:
def a(self):
print('Spam.a')
def b(self):
print('Spam.b')

>>>

Ahora, cree una clase que la envuelva y redefina algunos de los métodos:

>>> class MySpam:
def __init__(self):
self._spam = Spam()
def a(self):
print('MySpam.a')
self._spam.a()
def c(self):
print('MySpam.c')
def __getattr__(self, name):
return getattr(self._spam, name)

>>> s = MySpam()
>>> s.a()
MySpam.a
Spam.a
>>> s.b()
Spam.b
>>> s.c()
MySpam.c
>>>

Observe con atención que la clase resultante se parece mucho a la herencia. Por ejemplo, el método a() está haciendo algo similar a la llamada super(). El método b() se toma a través del método __getattr__() que delega a la instancia Spam internamente almacenada.

Discusión

El método __getattr__() se define comúnmente en clases que actúan como envoltorios alrededor de otros objetos. Sin embargo, debe tener en cuenta que el proceso de envolver otro objeto de esta manera a menudo introduce otras complejidades. Por ejemplo, el objeto envoltorio puede interrumpir la verificación de tipos si cualquier otra parte de la aplicación está usando la función isinstance().

La delegación de métodos a través de __getattr__() tampoco funciona con métodos especiales como __getitem__(), __enter__(), etc. Si una clase hace un uso extensivo de dichos métodos, deberá proporcionar funciones similares en su clase contenedora.
