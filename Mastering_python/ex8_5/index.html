Ejercicio 8.5

Objetivos:

  • Aprender sobre generadores administrados

Archivos creados: multitask.py, server.py

Una función de generador o corrutina nunca puede ejecutarse sin ser controlada por otro código. Por ejemplo, un generador utilizado para iterar no realiza ninguna acción a menos que la iteración se realice mediante un bucle for. De igual manera, una colección de corrutinas no se ejecutará a menos que se invoque su método send() de alguna manera.

En aplicaciones avanzadas de generadores, es posible controlarlos de diversas maneras inusuales. En este ejercicio, veremos algunos ejemplos.

(a) Generadores como tareas

Si se trata de un archivo multitask.py, defina el siguiente código:

# multitask.py

from collections import deque
# multitask.py

from collections import deque

tasks = deque()
def run():
    while tasks:
        task = tasks.popleft()
        try:
            task.send(None)
            tasks.append(task)
        except StopIteration:
            print('Tarea completada')

Este código implementa un pequeño programador de tareas que ejecuta funciones de generador. Pruébelo ejecutándolo en las siguientes funciones.

# multitask.py
...

def countdown(n):
    while n > 0:
        print('T-menos', n)
        yield
        n -= 1

def countup(n):
    x = 0
    while x < n:
        print('Arriba', x)
        yield
        x += 1

if __name__ == '__main__':
    tasks.append(countdown(10))
    tasks.append(countdown(5))
    tasks.append(countup(20))
    run()

(b) Generadores como tareas que sirven conexiones de red

Cree un archivo server.py e introduzca el siguiente código:

# server.py

from socket import *
from select import select
from collections import deque

tasks = deque()
recv_wait = {}   #  sock -> task
send_wait = {}   #  sock -> task

def run():
    while any([tasks, recv_wait, send_wait]):
        while not tasks:
            can_recv, can_send, _ = select(recv_wait, send_wait, [])
            for s in can_recv:
                tasks.append(recv_wait.pop(s))
            for s in can_send:
                tasks.append(send_wait.pop(s))
        task = tasks.popleft()
        try:
            reason, resource = task.send(None)
            if reason == 'recv':
                recv_wait[resource] = task
            elif reason == 'send':
                send_wait[resource] = task
            else:
                raise RuntimeError('Razón desconocida %r' % reason)
        except StopIteration:
            print('Tarea completada')

Este código es una versión un poco más compleja del programador de tareas de la parte (a). Requerirá un poco de estudio, pero la idea es que cada tarea no solo ceda, sino que también indique una razón para hacerlo (recibir o enviar). Dependiendo de la razón, la tarea se moverá a una zona de espera. El programador entonces ejecuta cualquier tarea disponible o espera a que se produzcan eventos de E/S cuando no queda nada por hacer.

Quizás sea un poco complicado, pero añade el siguiente código que implementa un servidor de eco simple:

# server.py
...

def tcp_server(address, handler):
    sock = socket(AF_INET, SOCK_STREAM)
    sock.setsockopt(SOL_SOCKET, SO_REUSEADDR, 1)
    sock.bind(address)
    sock.listen(5)
    while True:
        yield 'recv', sock
        client, addr = sock.accept()
        tasks.append(handler(client, addr))

def echo_handler(client, address):
    print('Conexión desde', address)
    while True:
        yield 'recv', client
        data = client.recv(1000)
        if not data:
            break
        yield 'send', client
        client.send(b'GOT:' + data)
    print('Conexión cerrada')

if __name__ == '__main__':
    tasks.append(tcp_server(('',25000), echo_handler))
    run()

Ejecute este servidor en su propia ventana de terminal. En otra terminal, conéctese a él usando un comando como telnet o nc. Por ejemplo:

bash % nc localhost 25000
Hola

Mundo
Got: Mundo

Si no tiene acceso a nc o telnet, también puede usar Python:

bash % python3 -m telnetlib localhost 25000
Hola
Got: Hola
Mundo
Got: Mundo

Si funciona, debería ver la salida en eco. Además, si conecta varios clientes, todos funcionarán simultáneamente. Este uso complejo de los generadores no es algo que probablemente tengas que codificar directamente. Sin embargo, se utilizan en ciertos paquetes avanzados como asyncio, que se añadió a la biblioteca estándar en Python 3.4.
