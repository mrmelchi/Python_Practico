(a) Crecimiento de la lista

Las listas de Python están altamente optimizadas para realizar operaciones append(). Cada vez que una lista crece, toma una porción más grande de memoria de la que realmente necesita con la expectativa de que se agregarán más datos a la lista más adelante. Si se agregan nuevos elementos y hay espacio disponible, la operación append() almacena el elemento sin asignar más memoria.

Experimente con esta característica de las listas usando la función sys.getsizeof() en una lista y agregando algunos elementos más.

>>> import sys
>>> items = []
>>> sys.getsizeof(items)
64
>>> items.append(1)
>>> sys.getsizeof(items)
96
>>> items.append(2)
>>> sys.getsizeof(items) # Observa cómo el tamaño no aumenta
96
>>> items.append(3)
>>> sys.getsizeof(items) # Aquí todavía no aumenta
96
>>> items.append(4)
>>> sys.getsizeof(items) # Todavía no.
96
>>> items.append(5)
>>> sys.getsizeof(items) # Observa que el tamaño ha aumentado
128
>>>

Una lista almacena sus elementos por referencia. Por lo tanto, la memoria necesaria para cada elemento es una única dirección de memoria. En una máquina de 64 bits, una dirección suele tener 8 bytes. Sin embargo, si Python se ha compilado para 32 bits, puede tener 4 bytes y los números del ejemplo anterior serán la mitad de lo que se muestra.

(b) Crecimiento de diccionarios/clases

Los diccionarios (y clases) de Python permiten almacenar hasta 5 valores antes de que se duplique su memoria reservada. Investigue creando un diccionario y agregándole algunos valores más:

>>> row = { 'route': '22', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354 }
>>> sys.getsizeof(row)
240
>>> row['a'] = 1
>>> sys.getsizeof(row)
240
>>> row['b'] = 2
>>> sys.getsizeof(row)
368
>>>

¿Se agota la memoria si elimina el elemento que acaba de agregar?

Para reflexionar: si está creando una gran cantidad de registros, representar cada registro como un diccionario podría no ser el enfoque más eficiente; podría estar pagando un alto precio por la conveniencia de tener un diccionario. Tal vez sea mejor considerar el uso de tuplas, tuplas con nombre o clases que definan __slots__.

(c) Cambiar la orientación (a columnas)

A menudo, puede ahorrar mucha memoria si cambia la vista de los datos. Por ejemplo, ¿qué sucede si lee todos los datos del bus en columnas usando esta función?

# readrides.py

...

def read_rides_as_columns(filename):
    '''
    Read the bus ride data into 4 lists, representing columns
    '''
    routes = []
    dates = []
    daytypes = []
    numrides = []
    with open(filename) as f:
        rows = csv.reader(f)
        headings = next(rows)     # Omitir encabezados
        for row in rows:
            routes.append(row[0])
            dates.append(row[1])
            daytypes.append(row[2])
            numrides.append(int(row[3]))
    return dict(routes=routes, dates=dates, daytypes=daytypes, numrides=numrides)

En teoría, esta función debería ahorrar mucha memoria. Analicémosla antes de probarla.

En primer lugar, el archivo de datos contenía 577563 filas de datos, donde cada fila contenía cuatro valores. Si cada fila se almacena como un diccionario, entonces esos diccionarios tienen un tamaño mínimo de 240 bytes.

>>> nrows = 577563 # Número de filas en el archivo original
>>> nrows * 240
138615120
>>>

Por lo tanto, son 138 MB solo para los diccionarios en sí. Esto no incluye ninguno de los valores almacenados realmente en los diccionarios.

Al cambiar a columnas, los datos se almacenan en 4 listas separadas. Cada lista requiere 8 bytes por elemento para almacenar un puntero. Entonces, aquí hay una estimación aproximada de los requisitos de la lista:

>>> nrows * 4 * 8
18482016
>>>

Eso es aproximadamente 18 MB de sobrecarga de lista. Por lo tanto, cambiar a una orientación de columna debería ahorrar aproximadamente 120 MB de memoria únicamente al eliminar toda la información adicional que se debe almacenar en los diccionarios.

Intente usar esta función para leer los datos del bus y observar el uso de memoria.

>>> tracemalloc.start()
>>> columnas = read_rides_as_columns('Data/ctabus.csv')
>>> tracemalloc.get_traced_memory()
... observe el resultado...
>>>

(d) Creación de un contenedor personalizado: la gran falsificación

Almacenar los datos en columnas permite ahorrar mucha más memoria, pero ahora resulta bastante extraño trabajar con los datos. De hecho, ninguno de nuestros códigos de análisis anteriores del Ejercicio 2.2 puede funcionar con columnas. La razón por la que todo está roto es que has roto la abstracción de datos que se utilizó en ejercicios anteriores, es decir, la suposición de que los datos se almacenan como una lista de diccionarios.

Esto se puede solucionar si estás dispuesto a crear un objeto contenedor personalizado que lo "falsifique". Hagámoslo.

El código de análisis anterior asume que los datos se almacenan en una secuencia de registros. Cada registro se representa como un diccionario. Comencemos creando una nueva clase "Sequence". En esta clase, almacenamos las cuatro columnas de datos que se estaban utilizando en la función read_rides_as_columns().

# readrides.py

import collections
...
class RideData(collections.abc.Sequence):
    def __init__(self):
        self.routes = [] # Columnas
        self.dates = []
        self.daytypes = []
        self.numrides = []

Intente crear una instancia de RideData. Verás que falla con un mensaje de error como este:

>>> records = RideData()
Traceback (most recent call last):
...
TypeError: Can't instantiate abstract class RideData with abstract methods __getitem__, __len__
>>>

Lee atentamente el mensaje de error. Nos dice lo que necesitamos implementar. Agreguemos un método __len__() y __getitem__(). En el método __getitem__(), crearemos un diccionario. Además, crearemos un método append() que toma un diccionario y lo descomprime en 4 operaciones append() independientes.

# readrides.py
...

class RideData(collections.abc.Sequence):
    def __init__(self):
        # Cada valor es una lista con todos los valores (una columna)
        self.routes = []
        self.dates = []
        self.daytypes = []
        self.numrides = []

    def __len__(self):
        # Se supone que todas las listas tienen la misma longitud
            return len(self.routes)

    def __getitem__(self, index):
        return { 'route': self.routes[index],
                 'date': self.dates[index],
                 'daytype': self.daytypes[index],
                 'rides': self.numrides[index] }

    def append(self, d):
        self.routes.append(d['route'])
        self.dates.append(d['date'])
        self.daytypes.append(d['daytype'])
        self.numrides.append(d['rides'])

Si lo has hecho correctamente, deberías poder colocar este objeto en la función read_rides_as_dicts() escrita anteriormente. Esto implica cambiar solo una línea de código:

def read_rides_as_dicts(filename):
    '''
    Lee los datos del recorrido en autobús como una lista de diccionarios
    '''
    records = RideData()      # <---  CAMBIE ESTO
    with open(filename) as f:
        rows = csv.reader(f)
        headings = next(rows)     # Omite encabezados
        for row in rows:
            route = row[0]
            date = row[1]
            daytype = row[2]
            rides = int(row[3])
            record = {
                'route': route, 
                'date': date, 
                'daytype': daytype, 
                'rides' : rides
                }

(e) Desafío

¿Qué sucede cuando tomas una porción de los datos de un recorrido?

>>> r = rows[0:10]
>>> r
... mira el resultado...
>>>

Probablemente se verá un poco loco. ¿Puedes modificar la clase RideData para que produzca una porción adecuada que parezca una lista de diccionarios? Por ejemplo, de esta manera:

>>> rows = readrides.read_rides_as_dicts('Data/ctabus.csv')
>>> rows
<readrides.RideData object at 0x10f5054a8>
>>> len(rows)
577563
>>> r = rows[0:10]
>>> r
<readrides.RideData object at 0x10f5068c8>
>>> len(r)
10
>>> r[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>> r[1]
{'route': '4', 'date': '01/01/2001', 'daytype': 'U', 'rides': 9288}
>>>
