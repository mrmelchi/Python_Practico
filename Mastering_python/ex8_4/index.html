Ejercicio 8.4

Objetivos:

  • Gestionar lo que sucede en las sentencias yield

Archivos modificados: follow.py, cofollow.py

(a) Cierre de un generador

Una pregunta frecuente sobre los generadores es su tiempo de vida y la recolección de basura. Por ejemplo, el generador follow() se ejecuta indefinidamente en un bucle while infinito. ¿Qué ocurre si el bucle de iteración que lo impulsa se detiene? Además, ¿hay alguna forma de finalizar el generador prematuramente?

Modifique la función follow() para que todo el código esté encerrado en un bloque try-except como este:

def follow(filename):
    try:
        with open(filename,'r') as f:
            f.seek(0,os.SEEK_END)
            while True:
                 line = f.readline()
                 if line == '':
                     time.sleep(0.1)    # Dormir brevemente para evitar esperas intensas
                     continue
                 yield line
    except GeneratorExit:
        print('Siguiente')

Ahora, pruebe algunos experimentos:

>>> from follow import follow
>>> # Experimento: Recolección de basura de un generador en ejecución
>>> f = follow('Data/stocklog.csv')
>>> next(f)
'"MO",70.29,"6/11/2007","09:30.09",-0.01,70.25,70.30,70.29,365314\n'
>>> del f
Siguiente
>>> # Experimento: Cerrar un generador
>>> f = follow('Data/stocklog.csv')
>>> for line in f:
        print(line,end='')
        if 'IBM' in line:
            f.close()

"VZ",42.91,"6/11/2007","09:34.28",-0.16,42.95,42.91,42.78,210151
"HPQ",45.76,"6/11/2007","09:34.29",0.06,45.80,45.76,45.59,257169
"GM",31.45,"6/11/2007","09:34.31",0.45,31.00,31.50,31.45,582429
...
"IBM",102.86,"6/11/2007","09:34.44",-0.21,102.87,102.86,102.77,147550
Siguiente
>>> for line in f:
        print(line, end='')    # Sin salida: el generador ha terminado

>>>

En estos experimentos, se puede observar que se genera una excepción GeneratorExit cuando un generador se somete a la recolección de elementos no utilizados o se cierra explícitamente mediante su método close().

Otro aspecto a explorar es si se puede reanudar la iteración en un generador al salir de un bucle for. Por ejemplo, prueba esto:

>>> f = follow('Data/stocklog.csv')
>>> for line in f:
        print(line,end='')
        if 'IBM' in line:
            break

"CAT",78.36,"6/11/2007","09:37.19",-0.16,78.32,78.36,77.99,237714
"VZ",42.99,"6/11/2007","09:37.20",-0.08,42.95,42.99,42.78,268459
...
"IBM",102.91,"6/11/2007","09:37.31",-0.16,102.87,102.91,102.77,190859
>>> # Reanudar iteración
>>> for line in f:
        print(line,end='')
        if 'IBM' in line:
            break

"AA",39.58,"6/11/2007","09:39.28",-0.08,39.67,39.58,39.31,243159
"HPQ",45.94,"6/11/2007","09:39.29",0.24,45.80,45.94,45.59,408919
...
"IBM",102.95,"6/11/2007","09:39.44",-0.12,102.87,102.95,102.77,225350
>>> del f
Siguiente
>>>

En general, puede interrumpir una iteración en ejecución y reanudarla más tarde si es necesario. Solo necesitas asegurarte de que el objeto generador no se cierre forzosamente ni se recolecte basura de alguna manera.

(b) Generación de excepciones

En el archivo cofollow.py, creaste una corrutina printer(). Modifique el código para detectar y reportar excepciones como esta:

# cofollow.py
...
@consumer
def printer():
    while True:
        try:
            item = yield
            print(item)
        except Exception as e:
            print('ERROR: %r' % e)

Ahora, haga un experimento:

>>> from cofollow import printer
>>> p = printer()
>>> p.send('hello')
hello
>>> p.send(42)
42
>>> p.throw(ValueError('It failed'))
ERROR: ValueError('It failed',)
>>> try:
        int('n/a')
    except ValueError as e:
        p.throw(e)

ERROR: ValueError("invalid literal for int() with base 10: 'n/a'",)
>>>

Observe que el generador en ejecución no finaliza debido a la excepción. Esto simplemente permite que la instrucción yield indique un error en lugar de recibir un valor.
