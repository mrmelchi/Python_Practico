Ejercicio 2.4

Objetivos:

  • Crear un nuevo tipo primitivo

En la mayoría de los programas, se utilizan los tipos primitivos como int, float y str para representar datos. Sin embargo, no está limitado solo a esos tipos. La biblioteca estándar tiene módulos como el módulo decimal y fractions que implementan nuevos tipos primitivos. También puede crear sus propios tipos siempre que comprenda los protocolos subyacentes que hacen que los objetos de Python funcionen. En este ejercicio, crearemos un nuevo tipo primitivo. Hay muchos pequeños detalles de los que preocuparse, pero esto le dará una idea general de lo que se requiere.

(a) Números enteros mutables

Los números enteros de Python normalmente son inmutables. Sin embargo, supongamos que desea crear un objeto entero mutable. Comience creando una clase como esta:

# mutint.py

class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

Pruébelo:

>>> a = MutInt(3)
>>> a
<__main__.MutInt object at 0x10e79d408>
>>> a.value
3
>>> a.value = 42
>>> a.value
42
>>> a + 10
Traceback (most recent call last):
File "<stdin>", line 1, in <module>
TypeError: unsupported operand type(s) for +: 'MutInt' and 'int'
>>>

Todo esto es muy emocionante excepto que nada funciona realmente con este nuevo Objeto MutInt. La impresión es horrible, ninguno de los operadores matemáticos funciona y es básicamente inútil. Bueno, excepto por el hecho de que su valor es mutable, que sí lo tiene.

(b) Corrección de la salida

Puede corregir la salida proporcionando al objeto métodos como __str__(), __repr__() y __format__(). Por ejemplo:

# mint.py

class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    def __str__(self):
        return str(self.value)

    def __repr__(self):
        return f'MutInt({self.value!r})'

    def __format__(self, fmt):
        return format(self.value, fmt)

Pruébelo:

>>> a = MutInt(3)
>>> print(a)
3
>>> a
MutInt(3)
>>> f'El valor es {a:*^10d}'
El valor es ****3*****
>>> a.value = 42
>>> a
MutInt(42)
>>>

(c) Operadores matemáticos

Puede hacer que un objeto funcione con varios operadores matemáticos si implementa los métodos apropiados para él. Sin embargo, es su responsabilidad reconocer otros tipos de datos e implementar el código de conversión apropiado. Modifique la clase MutInt dándole un método __add__() de la siguiente manera:

class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    ...

    def __add__(self, other):
        if isinstance(other, MutInt):
            return MutInt(self.value + other.value)
        elif isinstance(other, int):
            return MutInt(self.value + other)
        else:
            return NotImplemented

Con este cambio, debería descubrir que puede sumar tanto números enteros como números enteros mutables. El resultado es una instancia de MutInt. Agregar otros tipos de números genera un error:

>>> a = MutInt(3)
>>> b = a + 10
>>> b
MutInt(13)
>>> b.value = 23
>>> c = a + b
>>> c
MutInt(26)
>>> a + 3.5
Traceback (most recent call last):
File "<stdin>", line 1, in <module>
TypeError: unsupported operand type(s) for +: 'MutInt' and 'float'
>>>

Un problema con el código es que no funciona cuando se invierte el orden de los operandos. Considere lo siguiente:

>>> a + 10
MutInt(13)
>>> 10 + a
Traceback (most recent call last):
Archivo "<stdin>", línea 1, en <module>
TypeError: unsupported operand type(s) for +: 'int' and 'MutInt'
>>>

Esto ocurre porque el tipo int no tiene conocimiento de MutInt y está confundido. Esto se puede solucionar agregando un método __radd__(). Este método se llama si el primer intento de llamar a __add__() no funcionó con el objeto proporcionado.

class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    ...

    def __add__(self, other):
        if isinstance(other, MutInt):
            return MutInt(self.value + other.value)
        elif isinstance(other, int):
            return MutInt(self.value + other)
        else:
            return NotImplemented

__radd__ = __add__ # Operandos invertidos

Con este cambio, verá que la suma funciona:

>>> a = MutInt(3)
>>> a + 10
MutInt(13)
>>> 10 + a
MutInt(13)
>>>

Dado que nuestro entero es mutable, también puede hacer que reconozca el in situ operador add-update += implementando el método __iadd__():

class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    ...

    def __iadd__(self, other):
        if isinstance(other, MutInt):
            self.value += other.value
            return self
        elif isinstance(other, int):
            self.value += other
            return self
        else:
            return NotImplemented

Esto permite usos interesantes como este:

>>> a = MutInt(3)
>>> b = a
>>> a += 10
>>> a
MutInt(13)
>>> b # Observe que b también cambia
MutInt(13)
>>>

Puede parecer extraño que b también cambie, pero hay características sutiles como esta con los objetos Python integrados. Por ejemplo:

>>> a = [1,2,3]
>>> b = a
>>> a += [4,5]
>>> a
[1, 2, 3, 4, 5]
>>> b
[1, 2, 3, 4, 5]

>>> c = (1,2,3)
>>> d = c
>>> c += (4,5)
>>> c
(1, 2, 3, 4, 5)
>>> d # Explicar la diferencia con las listas
(1, 2, 3)
>>>

(d) Comparaciones

Un problema es que las comparaciones todavía no funcionan. Por ejemplo:

>>> a = MutInt(3)
>>> b = MutInt(3)
>>> a == b
False
>>> a == 3
False
>>>

Puedes solucionar esto agregando un método __eq__(). Se pueden usar otros métodos como __lt__(), __le__(), __gt__(), __ge__() para implementar otras comparaciones. Por ejemplo:

class MutInt:
    __slots__ = ['valor']

    def __init__(self, valor):
        self.valor = valor

    ...
    def __eq__(self, otro):
        if isinstance(other, MutInt):
            return self.valor == otro.valor
        elif isinstance(other, int):
            return self.valor == otro
        else:
            return NotImplemented

    def __lt__(self, otro):
        if isinstance(other, MutInt):
            return self.valor < otro.valor
        elif isinstance(other, int):
            return self.valor < otro
        else:
            return NotImplemented

Pruébelo:

>>> a = MutInt(3)
>>> b = MutInt(3)
>>> a == b
True
>>> c = MutInt(4)
>>> a < c
True
>>> a <= c
Traceback (most recent call last):
Archivo "<stdin>", línea 1, en <module>
TypeError: '<=' no es compatible entre instancias de 'MutInt' y 'MutInt'
>>>

El motivo por el que el operador <= falla es que no se proporcionó ningún método __le__(). Podrías codificarlo por separado, pero una forma más fácil de obtenerlo es usar el decorador @total_ordering:

from functools import total_ordering

@total_ordering
class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    ...

    def __eq__(self, other):
        if isinstance(other, MutInt):
            return self.value == other.value
        elif isinstance(other, int):
            return self.value == other
        else:
            return NotImplemented

    def __lt__(self, other):
        if isinstance(other, MutInt):
            return self.value < other.value
        elif isinstance(other, int):
            return self.value < other
        else:
            return NotImplemented

@total_ordering completa los métodos de comparación que faltan siempre que proporciones como mínimo un operador de igualdad y una de las otras relaciones.

(e) Conversiones

Tu nuevo tipo primitivo está casi completo. Quizás quieras darle la capacidad de trabajar con algunas conversiones comunes. Por ejemplo:

>>> a = MutInt(3)
>>> int(a)
Traceback (most recent call last):
Archivo "<stdin>", línea 1, en <módulo>
TypeError: el argumento int() debe ser una cadena, un objeto similar a bytes o un número, no 'MutInt'
>>> float(a)
Traceback (most recent call last):
Archivo "<stdin>", línea 1, en <módulo>
TypeError: el argumento float() debe ser una cadena, un objeto similar a bytes o un número, no 'MutInt'
>>>

Puede darle a su clase un método __int__() y __float__() para solucionar esto:

from functools import total_ordering

@total_ordering
class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    ...

    def __int__(self):
        return self.value

    def __float__(self):
        return float(self.value)

Ahora, puedes convertir correctamente:

>>> a = MutInt(3)
>>> int(a)
3
>>> float(a)
3.0
>>>

Como regla general, Python nunca convierte datos automáticamente. Por lo tanto, incluso aunque le hayas dado a la clase un método __int__(), MutInt no va a funcionar en todas las situaciones en las que se podría esperar un entero. Por ejemplo, indexación:

>>> names = ['Dave', 'Guido', 'Paula', 'Thomas', 'Lewis']
>>> a = MutInt(1)
>>> names[a]
Traceback (most recent call last):
Archivo "<stdin>", línea 1, en <module>
TypeError: los índices de lista deben ser enteros o porciones, no MutInt
>>>

Esto se puede solucionar dándole a MutInt un método __index__() que produzca un entero. Modifique la clase de esta manera:

from functools import total_ordering

@total_ordering
class MutInt:
    __slots__ = ['value']

    def __init__(self, value):
        self.value = value

    ...

    def __int__(self):
        return self.value

__index__ = __int__ # Hacer que la indexación funcione

Discusión Crear un nuevo tipo de datos primitivo es en realidad una de las tareas de programación más complicadas en Python. Hay muchos casos extremos y problemas de bajo nivel de los que preocuparse, especialmente en lo que respecta a cómo interactúa su tipo con otros tipos de Python. Probablemente, lo más importante que debe tener en cuenta es que puede personalizar casi todos los aspectos de cómo un objeto interactúa con el resto de Python si conoce los protocolos subyacentes. Si va a hacer esto, es recomendable que observe el código existente para ver si hay algo similar a lo que está tratando de hacer.
