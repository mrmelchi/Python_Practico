Ejercicio 5.2

Objetivos:

  • Devolver valores desde funciones

En este ejercicio, veremos brevemente los problemas relacionados con la devolución de valores desde funciones. A primera vista, parece que esto debería ser sencillo, pero surgen algunos problemas sutiles.

(a) Devolver múltiples valores

Suponga que está escribiendo código para analizar archivos de configuración que constan de líneas como esta:


name=value

Escriba una función parse_line(line) que tome dicha línea y devuelva tanto el nombre como el valor asociados. La convención común para devolver múltiples valores es devolverlos en una tupla. Por ejemplo:

>>> parse_line('email=guido@python.org')
('email', 'guido@python.org')
>>> name, val = parse_line('email=guido@python.org')
>>> name
'email'
>>> val
'guido@python.org'
>>>

(b) Devolución de valores opcionales

A veces, una función puede devolver un valor opcional, posiblemente como un mecanismo para indicar éxito o fracaso. La convención más común es utilizar None como representación de un valor faltante. Modifique la función parse_line() anterior para que devuelva una tupla en caso de éxito o None en caso de datos incorrectos. Por ejemplo:

>>> parse_line('email=guido@python.org')
('email', 'guido@python.org')
>>> parse_line('spam')       # Devuelve None
>>>

Discusión sobre el diseño: ¿sería mejor que la función parse_line() genere una excepción en los datos mal formados?

(c) Futuros

A veces, el código Python se ejecuta simultáneamente a través de subprocesos o procesos. Para ilustrarlo, prueba este ejemplo:

>>> import time
>>> def worker(x, y):
        print('A punto de trabajar')
        time.sleep(20)
        print('Hecho')
        return x + y

>>> worker(2, 3)     # Llamada de función normal
A punto de trabajar  
Hecho
5
>>>

Ahora, ejecuta worker() en un hilo separado:

>>> import threading
>>> t = threading.Thread(target=worker, args=(2, 3))
>>> t.start()
A punto de trabajar
>>>
Hecho

Observa con atención que el resultado del cálculo no aparece en ninguna parte. No solo eso, ni siquiera sabes cuándo se completará. Aquí hay un cierto problema de coordinación. La convención para manejar este caso es envolver el resultado de una función en un Futuro. Un Futuro representa un resultado futuro. Así es como funciona:

>>> from concurrent.futures import Future
>>> # Envoltorio alrededor de la función para usar un futuro
>>> def do_work(x, y, fut):
        fut.set_result(worker(x,y))

>>> fut = Future()
>>> t = threading.Thread(target=do_work, args=(2, 3, fut))
>>> t.start()
A punto de trabajar
>>> result = fut.result()
Hecho
>>> result
5
>>>

Verás este tipo de patrón mucho si trabajas con grupos de subprocesos, procesos y otras construcciones. Por ejemplo:

>>> from concurrent.futures import ThreadPoolExecutor
>>> pool = ThreadPoolExecutor()
>>> fut = pool.submit(worker, 2, 3)
A punto de trabajar
>>> fut
<Futuro en 0x102157080 estado=en ejecución>
>>> fut.result()
Hecho
5
>>>
