Ejercicio 7.3

Objetivos:

  • Aprender sobre los decoradores de clases
  • Repaso de los descriptores

Archivos modificados: validate.py, structure.py

Este ejercicio reunirá varios temas que hemos desarrollado en los últimos días. ¡Prepárense!

(a) Revisión de descriptores

En el Ejercicio 4.3 definió algunos descriptores que permitían al usuario definir clases con atributos con verificación de tipo, como este:

from validate import String, PositiveInteger, PositiveFloat

class Stock:
    name   = String()
    shares = PositiveInteger()
    price  = PositiveFloat()
    ...

Modifique su clase Stock para que incluya los descriptores anteriores y ahora tenga este aspecto (consulte el Ejercicio 6.4):

# stock.py

from structure import Structure
from validate import String, PositiveInteger, PositiveFloat

class Stock(Structure):
    _fields = ('name', 'shares', 'price')
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares

Stock.create_init()

Ejecuta las pruebas unitarias en teststock.py. Deberías ver que un número significativo de pruebas pasan correctamente con la comprobación de tipos. Excelente.

(b) Uso de decoradores de clase para completar detalles

Un aspecto molesto del código anterior es que hay detalles adicionales, como la variable _fields y el paso final de Stock.create_init(). Gran parte de esto podría empaquetarse en un decorador de clase.

En el archivo structure.py, crea un decorador de clase @validate_attributes que examine el cuerpo de la clase en busca de instancias de validadores y complete la variable _fields. Por ejemplo:

# structure.py

from validate import Validator

def validate_attributes(cls):
    validators = []
    for name, val in vars(cls).items():
        if isinstance(val, Validator):
            validators.append(val)
    cls._fields = [val.name for val in validators]
    return cls

Este código se basa en el hecho de que los diccionarios de clases están ordenados a partir de Python 3.6. Por lo tanto, encontrará los diferentes descriptores de Validator en el orden en que aparecen. Usando este orden, puede completar la variable _fields. Esto te permite escribir código como este:

# stock.py

from structure import Structure, validate_attributes
from validate import String, PositiveInteger, PositiveFloat

@validate_attributes
class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares

Stock.create_init()

Una vez que esto funcione, modifica el decorador @validate_attributes para realizar adicionalmente el paso final de llamar a Stock.create_init(). Esto reducirá la clase a lo siguiente:

# stock.py

from structure import Structure, validate_attributes
from validate import String, PositiveInteger, PositiveFloat

@validate_attributes
class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares

(c) Aplicación de decoradores mediante herencia

Tener que especificar el decorador de la clase es un poco molesto. Modifique la clase Structure con el siguiente método __init_subclass__():

# structure.py

class Structure:
    ...
    @classmethod
    def __init_subclass__(cls):
        validate_attributes(cls)

Una vez realizado este cambio, debería poder eliminar por completo el decorador y confiar únicamente en la herencia. ¡Es herencia con un toque mágico!

# stock.py

from structure import Structure
from validate import String, PositiveInteger, PositiveFloat

class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares):
        self.shares -= nshares

Ahora, el código realmente está empezando a funcionar. De hecho, parece casi normal. Sigamos intentándolo.

(d) Conversión de filas

Una característica que falta en la clase Structure es el método from_row() que le permite trabajar con código de lectura CSV anterior. Vamos a solucionarlo. Asigne a la clase Structure una variable de clase _types y el siguiente método de clase:

# structure.py

class Structure:
    _types = ()
    ...
    @classmethod
    def from_row(cls, row):
        rowdata = [ func(val) for func, val in zip(cls._types, row) ]
        return cls(*rowdata)
    ...

Modifica el decorador @validate_attributes para que examine los distintos validadores de un atributo expected_type y lo use para completar la variable _types anterior.

Una vez hecho esto, deberías poder hacer cosas como esta:

>>> s = Stock.from_row(['GOOG', '100', '490.1'])
>>> s
Stock('GOOG', 100, 490.1)
>>> import reader
>>> port = reader.read_csv_as_instances('Data/portfolio.csv', Stock)
>>>

(e) Comprobación de argumentos del método

¿Recuerdas el decorador @validated que escribiste en la parte anterior? Modifiquemos el decorador @validate_attributes para que cualquier método de la clase con anotaciones se envuelva automáticamente con @validated. Esto permite aplicar anotaciones obligatorias a métodos como el método sell():

# stock.py

from structure import Structure
from validate import String, PositiveInteger, PositiveFloat

class Stock(Structure):
    name = String()
    shares = PositiveInteger()
    price = PositiveFloat()

    @property
    def cost(self):
        return self.shares * self.price

    def sell(self, nshares: PositiveInteger):
        self.shares -= nshares

Verás que sell() ahora aplica el argumento.

>>> s = Stock('GOOG', 100, 490.1)
>>> s.sell(25)
>>> s.sell(-25)
Traceback (most recent call last):
  ...
TypeError: Bad Arguments
  nshares: must be >= 0
>>>

Sí, esto se está poniendo muy interesante. La combinación de un decorador de clase y la herencia es una fuerza poderosa.
