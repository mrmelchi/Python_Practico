Ejercicio 2.6

Objetivos:

  • Explorar el poder de tener objetos de primera clase.
  • Comprender mejor el modelo de memoria de Python

Archivos creados: reader.py

En ejercicios anteriores, escribiste varias funciones para leer datos CSV en diferentes archivos. Seguramente este es un problema que podría generalizarse de alguna manera. En este ejercicio, exploramos esa idea.

(a) Datos de primera clase

En el archivo Data/portfolio.csv, se leen los datos organizados en columnas que se ven así:

"AA",100,32.20
"IBM",50,91.10
...

En el código anterior, estos datos se procesaban codificando de forma rígida todas las conversiones de tipos. Por ejemplo:

rows = csv.reader(f)
for row in rows:
    name   = row[0]
    shares = int(row[1])
    price  = float(row[2])

Este tipo de conversión también se puede realizar de una manera más inteligente utilizando algunas operaciones de lista. Crea una lista de Python que contenga las conversiones que quieres realizar en cada columna:

>>> coltypes = [str, int, float]
>>>

La razón por la que puedes crear esta lista es que todo en Python es de "primera clase". Por lo tanto, si quieres tener una lista de funciones, está bien.

Ahora, lee una fila de datos del archivo anterior:

>>> import csv
>>> f = open('Data/portfolio.csv')
>>> rows = csv.reader(f)
>>> headers = next(rows)
>>> row = next(rows)
>>> row
['AA', '100', '32.20']
>>>

Comprime los tipos de columna con la fila y observa el resultado:

>>> r = list(zip(coltypes, row))
>>> r
[(<class 'str'>, 'AA'), (<class 'int'>, '100'), (<class 'float'>,'32.20')]
>>>

Notarás que esto ha emparejado una conversión de tipo con un valor. Por ejemplo, int se empareja con el valor '100'. Ahora, prueba esto:

>>> record = [func(val) for func, val in zip(coltypes, row)]
>>> record
['AA', 100, 32.2]
>>>

Asegúrate de entender lo que está sucediendo en el código anterior. En el bucle, la variable func es una de las funciones de conversión de tipo (por ejemplo, str, int, etc.) y la variable val es uno de los valores como 'AA', '100'. La expresión func(val) convierte un valor (algo así como una conversión de tipo).

Puedes llevarlo un paso más allá y crear diccionarios utilizando los encabezados de columna. Por ejemplo:

>>> dict(zip(headers, record))
{'name': 'AA', 'shares': 100, 'price': 32.2}
>>>

Si lo prefiere, puede realizar todos estos pasos a la vez utilizando una comprensión de diccionario:

>>> { name:func(val) for name, func, val in zip(headers, coltypes, row) }
{'name': 'AA', 'shares': 100, 'price': 32.2}
>>>

(b) Creación de una función de utilidad de análisis

Cree un nuevo archivo reader.py. En ese archivo, defina una función de utilidad read_csv_as_dicts() que lea un archivo de datos CSV en una lista de diccionarios donde el usuario especifica las conversiones de tipo para cada columna.

Así es como debería funcionar:

>>> import reader
>>> portfolio = reader.read_csv_as_dicts('Data/portfolio.csv', [str,int,float])
>>> for s in portfolio:
        print(s)

{'name': 'AA', 'shares': 100, 'price': 32.2}
{'name': 'IBM', 'shares': 50, 'price': 91.1}
{'name': 'CAT', 'shares': 150, 'price': 83.44}
{'name': 'MSFT', 'shares': 200, 'price': 51.23}
{'name': 'GE', 'shares': 95, 'price': 40.37}
{'name': 'MSFT', 'shares': 50, 'price': 65.1}
{'name': 'IBM', 'shares': 100, 'price': 70.44}
>>>

O, si desea leer los datos de CTA:

>>> rows = reader.read_csv_as_dicts('Data/ctabus.csv', [str,str,str,int])
>>> len(rows)
577563
>>> rows[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>>

(c) Memoria: Revisión

En el Ejercicio 2.1 exploramos el uso de la memoria y en Ejercicio 2.2, determinamos que había 181 rutas de autobús únicas en Chicago.

>>> routes = { row['route'] for row in rows }
>>> len(routes)
181
>>>

Pregunta: ¿Cuántos objetos de cadena de ruta únicos están contenidos en los datos del recorrido? En lugar de crear un conjunto de rutas, cree un conjunto de identificadores de objetos:

>>> routeids = { id(row['route']) for row in rows }
>>> len(routeids)
542305

Piense en esto por un momento: solo hay 181 nombres de ruta distintos, pero la lista de diccionarios resultante contiene 542305 cadenas de ruta diferentes. Tal vez esto sea algo que se pueda solucionar con un poco de almacenamiento en caché o reutilización de objetos. Resulta que Python tiene una función que se puede usar para almacenar en caché cadenas: sys.intern(). Por ejemplo:

>>> a = 'hello world'
>>> b = 'hello world'
>>> a is b
False
>>> import sys
>>> a = sys.intern(a)
>>> b = sys.intern(b)
>>> a is b
True
>>>

Reinicie Python y pruebe esto:

>>> # ------------------ RESTART ---------```
>>> import tracemalloc
>>> tracemalloc.start()
>>> from sys import intern
>>> import reader
>>> rows = reader.read_csv_as_dicts('Data/ctabus.csv', [intern, str, str, int])
>>> routeids = { id(row['route']) for row in rows }
>>> len(routeids)
181
>>>

Observe el uso de la memoria.

>>> tracemalloc.get_traced_memory()
... observe el resultado...
>>>

La memoria debería disminuir bastante. Observación: también hay mucha repetición en las fechas. ¿Qué sucede si también almacena en caché las cadenas de fecha?

>>> # ------------------ RESTART ---------```
>>> import tracemalloc
>>> tracemalloc.start()
>>> from sys import intern
>>> import reader
>>> rows = reader.read_csv_as_dicts('Data/ctabus.csv', [intern, intern, str, int])
>>> tracemalloc.get_traced_memory()
... mira el resultado ...
>>>

(d) Proyecto de desafío especial

En el Ejercicio 2.5, creamos una clase RideData que almacenaba todos los datos del autobús en columnas, pero en realidad presentaba los datos a un usuario como una secuencia de diccionarios. Ahorró mucha memoria a través de varias formas de magia.

¿Puedes generalizar esa idea? En concreto, ¿puede crear una función de propósito general read_csv_as_columns() que funcione de esta manera:

>>> data = read_csv_as_columns('Data/ctabus.csv', types=[str, str, str, int])
>>> data
<__main__.DataCollection object at 0x102b45048>
>>> len(data)
577563
>>> data[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>> data[1]
{'route': '4', 'date': '01/01/2001', 'daytype': 'U', 'rides': 9288}
>>> data[2]
{'route': '6', 'date': '01/01/2001', 'daytype': 'U', 'rides': 6048}
>>>

Se supone que esta función es de propósito general: puede proporcionarle cualquier archivo y una lista de los tipos de columnas y leerá los datos. Los datos se leen en una clase DataCollection que almacena los datos como columnas internamente. Sin embargo, los datos se presentan como una secuencia de diccionarios cuando se accede a ellos.

Intente usar esta función con el truco de internación de cadenas de la última parte. ¿Cuánta memoria se necesita para almacenar todos los datos de los viajes ahora? ¿Puede seguir usando esta función con su código de análisis de CTA anterior?

(e) Pensamiento profundo

En este ejercicio, ha escrito dos funciones, read_csv_as_dicts() y read_csv_as_columns(). Estas funciones presentan datos al usuario de la misma manera. Por ejemplo:

>>> data1 = read_csv_as_dicts('Data/ctabus.csv', [str, str, str, int])
>>> len(data1)
577563
>>> data1[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>> data1[1]
{'route': '4', 'date': '01/01/2001', 'daytype': 'U', 'rides': 9288}
>>>

>>> data2 = read_csv_as_columns('Data/ctabus.csv', [str, str, str, int])
>>> len(data2)
577563
>>> data2[0]
{'route': '3', 'date': '01/01/2001', 'daytype': 'U', 'rides': 7354}
>>> data2[1]
{'route': '4', 'date': '01/01/2001', 'daytype': 'U', 'rides': 9288}
>>>

De hecho, puedes usar cualquiera de las dos funciones en el código de análisis de datos de CTA que escribiste. Sin embargo, en segundo plano están sucediendo cosas completamente diferentes. La función read_csv_as_columns() almacena los datos en una representación diferente. Se basa en protocolos de secuencia de Python (métodos mágicos) para presentarte la información de una manera más útil.

Esto es realmente parte de un concepto de programación mucho más grande de "Abstracción de datos". Al escribir programas, la forma en que se presentan los datos suele ser más importante que la forma en que se organizan en realidad. Aunque presentamos los datos como una secuencia de diccionarios, existe una gran flexibilidad en la forma en que esto sucede en segundo plano. Es una idea poderosa y algo en lo que pensar al escribir sus propios programas.
