Ejercicio 4.2

Objetivos:

  • Aprender más sobre el comportamiento de la herencia
  • Entender el comportamiento de super().
  • Herencia más cooperativa.

Archivos creados: validate.py

(a) Las direcciones de la herencia

Python tiene dos "direcciones" diferentes de herencia. La primera se encuentra en el concepto de "herencia simple", donde una serie de clases heredan de un solo padre. Por ejemplo, prueba este ejemplo:

>>> class A:
        def spam(self):
            print('A.spam')

>>> class B(A):
        def spam(self):
            print('B.spam')
            super().spam()

>>> class C(B):
        def spam(self):
            print('C.spam')
            super().spam()


>>> C.__mro__
(<class '__main__.C'>, <class '__main__.B'>, <class '__main__.A'>, <class 'object'>)
>>> c = C()
>>> c.spam()
C.spam
B.spam
A.spam
>>>

Observa que el atributo __mro__ de la clase C codifica todos sus ancestros en orden. Cuando invoca el método spam(), este recorre la jerarquía clase por clase del MRO.

Con la herencia múltiple, obtiene un tipo diferente de herencia que permite que se compongan diferentes clases juntas. Pruebe este ejemplo:

>>> class Base:
        def spam(self):
            print('Base.spam')

>>> class X(Base):
        def spam(self):
            print('X.spam')
            super().spam()

>>> class Y(Base):
        def spam(self):
            print('Y.spam')
            super().spam()

>>> class Z(Base):
        def spam(self):
            print('Z.spam')
            super().spam()

>>>

Observe que todas las clases anteriores heredan de una clase principal común Base. Sin embargo, las clases X, Y y Z no están directamente relacionadas entre sí (no hay una cadena de herencia que vincule esas clases).

Sin embargo, observe lo que sucede en la herencia múltiple:

>>> class M(X,Y,Z):
        pass

>>> M.__mro__
(<class '__main__.M'>, <class '__main__.X'>, <class '__main__.Y'>, <class '__main__.Z'>, <class '__main__.Base'>, <class 'object'>)
>>> m = M()
>>> m.spam()
X.spam
Y.spam
Z.spam
Base.spam

Aquí, puede ver que todas las clases se apilan juntas en el orden proporcionado por la subclase. Supongamos que la subclase reorganiza el orden de las clases:

>>> class N(Z,Y,X):
        pass

>>> N.__mro__
(<class '__main__.N'>, <class '__main__.Z'>, <class '__main__.Y'>, <class '__main__.X'>, <class '__main__.Base'>, <class 'object'>)
>>> n = N()
>>> n.spam()
Z.spam
Y.spam
X.spam
Base.spam
>>>

Aquí, puede ver que el orden de los padres cambia. Preste atención cuidadosamente a lo que super() está haciendo en ambos casos. No delega al padre inmediato de cada clase; en cambio, pasa a la siguiente clase en el MRO. No solo eso, el orden exacto lo controla el hijo. Esto es bastante extraño.

Observe también que el padre común Base sirve para terminar la cadena de operaciones super(). Específicamente, el método Base.spam() no llama a ningún otro método. También aparece al final del MRO, ya que es el padre de todas las clases que se componen juntas.

(b) Construya un verificador de valores

En el Ejercicio 3.4, agregó algunas propiedades a la clase Stock que verificaban los atributos para diferentes tipos y valores (por ejemplo, las acciones tenían que ser un entero positivo). Juguemos un poco con esa idea. Comience creando un archivo validate.py y defina la siguiente clase base:

# validate.py
class Validator:
    @classmethod
    def check(cls, value):
        return value

Ahora, hagamos algunas clases para la verificación de tipos:

class Typed(Validator):
    expected_type = object
    @classmethod
    def check(cls, value):
        if not isinstance(value, cls.expected_type):
            raise TypeError(f'Expected {cls.expected_type}')
        return super().check(value)

class Integer(Typed):
    expected_type = int

class Float(Typed):
    expected_type = float

class String(Typed):
    expected_type = str

A continuación, se muestra cómo usar estas clases (Nota: el uso de @classmethod nos permite evitar el paso adicional de creando instancias que realmente no necesitamos):

>>> Integer.check(10)
10
>>> Integer.check('10')
Traceback (most recent call last):
  File "<stdin>", line 1, in check
    raise TypeError(f'Expected {cls.expected_type}')
TypeError: Expected <class 'int'>
>>> String.check('10')
'10'
>>>

Podrías usar los validadores en una función. Por ejemplo:

>>> def add(x, y):
        Integer.check(x)
        Integer.check(y)
        return x + y

>>> add(2, 2)
4
>>> add('2', '3')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<stdin>", line 2, in add
  File "validate.py", line 11, in check
    raise TypeError(f'Expected {cls.expected_type}')
TypeError: Expected <class 'int'>
>>>

Ahora, cree más clases para diferentes tipos de verificación de dominio:

class Positive(Validator):
    @classmethod
    def check(cls, value):
        if value < 0:
            raise ValueError('Expected >= 0')
        return super().check(value)

class NonEmpty(Validator):
    @classmethod
    def check(cls, value):
        if len(value) == 0:
            raise ValueError('Must be non-empty')
        return super().check(value)

¿Adónde va todo esto? Comencemos a componer clases juntas con herencia múltiple como bloques de juguete:

class PositiveInteger(Integer, Positive):
    pass

class PositiveFloat(Float, Positive):
    pass

class NonEmptyString(String, NonEmpty):
    pass

Básicamente, estás tomando validadores existentes y componiéndolos juntos para formar otros nuevos. ¡Qué locura! Sin embargo, usémoslos para validar algunas cosas ahora:

>>> PositiveInteger.check(10)
10
>>> PositiveInteger.check('10')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    raise TypeError(f'Expected {cls.expected_type}')
TypeError: Expected <class 'int'>
>>> PositiveInteger.check(-10)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    raise ValueError('Expected >= 0')
ValueError: Must be >= 0


>>> NonEmptyString.check('hello')
'hello'
>>> NonEmptyString.check('')
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
    raise ValueError('Must be non-empty')
ValueError: Must be non-empty
>>>

En este punto, probablemente tu cabeza esté completamente aturdida. Sin embargo, el problema de componer diferentes fragmentos de código juntos es uno que surge en los programas del mundo real. La herencia múltiple cooperativa es una de las herramientas que se pueden utilizar para organizarlo.

(c) Uso de sus validadores

Sus validadores se pueden utilizar para agregar verificación de valores a funciones y clases. Por ejemplo, tal vez los validadores se podrían usar en las propiedades de Stock:

class Stock:
    ...
    @property
    def shares(self):
        return self._shares

    @shares.setter
    def shares(self, value):
        self._shares = PositiveInteger.check(value)
    ...

Copia la clase Stock de stock.py cámbiala para usar los validadores en el código de propiedad para shares y price.
