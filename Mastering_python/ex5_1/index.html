Ejercicio 5.1

Objetivos:

  • Explorar algunos aspectos definitorios de funciones/métodos
  • Hacer que las funciones sean más flexibles
  • Sugerencias de tipo

En el Ejercicio 2.6 escribió un módulo reader.py que tenía una función para leer un CSV en una lista de diccionarios. Por ejemplo:

>>> import reader
>>> port = reader.read_csv_as_dicts('Data/portfolio.csv', [str,int,float])
>>>

Más tarde ampliamos ese código para trabajar con instancias en Ejercicio 3.3:

>>> import reader
>>> from stock import Stock
>>> port = reader.read_csv_as_instances('Data/portfolio.csv', Stock)
>>>

Finalmente, el código se refactorizó en una colección de clases que involucran herencia en Ejercicio 3.7. Sin embargo, el código se ha vuelto bastante complejo y enrevesado.

(a) Volver a lo básico

Comience por revertir los cambios relacionados con las definiciones de clase. Reescribe el archivo reader.py para que contenga las dos funciones básicas que tenías antes de arruinarlo con clases:

# reader.py

import csv

def read_csv_as_dicts(filename, types):
    '''
    Lee datos CSV en una lista de diccionarios con conversión de tipo opcional
    '''
    records = []
    with open(filename) as file:
        rows = csv.reader(file)
        headers = next(rows)
        for row in rows:
            record = { name: func(val) 
                       for name, func, val in zip(headers, types, row) }
            records.append(record)
    return records

def read_csv_as_instances(filename, cls):
    '''
    Lee datos CSV en una lista de instancias
    '''
    records = []
    with open(filename) as file:
        rows = csv.reader(file)
        headers = next(rows)
        for row in rows:
            record = cls.from_row(row)
            records.append(record)
    return records

Asegúrese de que el código todavía funciona como lo hacía antes:

>>> import reader
>>> port = reader.read_csv_as_dicts('Data/portfolio.csv', [str, int, float])
>>> port
[{'name': 'AA', 'shares': 100, 'price': 32.2}, {'name': 'IBM', 'shares': 50, 'price': 91.1}, 
 {'name': 'CAT', 'shares': 150, 'price': 83.44}, {'name': 'MSFT', 'shares': 200, 'price': 51.23}, 
 {'name': 'GE', 'shares': 95, 'price': 40.37}, {'name': 'MSFT', 'shares': 50, 'price': 65.1}, 
 {'name': 'IBM', 'shares': 100, 'price': 70.44}]
>>> import stock
>>> port = reader.read_csv_as_instances('Data/portfolio.csv', stock.Stock)
>>> port

 Stock('MSFT', 200, 51.23), Stock('GE', 95, 40.37), Stock('MSFT', 50, 65.1), 
 Stock('IBM', 100, 70.44)]
>>>

(b) Pensando en la flexibilidad

En este momento, las dos funciones en reader.py están programadas para funcionar con nombres de archivos que se pasan directamente a open(). Refactorice el código para que funcione con cualquier objeto iterable que produzca líneas. Para ello, cree dos nuevas funciones csv_as_dicts(lines, types) y csv_as_instances(lines, cls) que conviertan cualquier secuencia iterable de líneas. Por ejemplo:

>>> file = open('Data/portfolio.csv')
>>> port = reader.csv_as_dicts(file, [str, int, float])
>>> port
[{'name': 'AA', 'shares': 100, 'price': 32.2}, {'name': 'IBM', 'shares': 50, 'price': 91.1}, 
 {'name': 'CAT', 'shares': 150, 'price': 83.44}, {'name': 'MSFT', 'shares': 200, 'price': 51.23}, 
 {'name': 'GE', 'shares': 95, 'price': 40.37}, {'name': 'MSFT', 'shares': 50, 'price': 65.1}, 
 {'name': 'IBM', 'shares': 100, 'price': 70.44}]
>>>

El objetivo de hacer esto es permitir trabajar con diferentes tipos de fuentes de entrada. Por ejemplo:

>>> import gzip
>>> import stock
>>> file = gzip.open('Data/portfolio.csv.gz', 'rt')
>>> port = reader.csv_as_instances(file, stock.Stock)
>>> port
[Stock('AA', 100, 32.2), Stock('IBM', 50, 91.1), Stock('CAT', 150, 83.44), 
 Stock('MSFT', 200, 51.23), Stock('GE', 95, 40.37), Stock('MSFT', 50, 65.1), 
 Stock('IBM', 100, 70.44)]
>>>

Para mantener la compatibilidad con versiones anteriores de código, escriba funciones read_csv_as_dicts() y read_csv_as_instances() que toman un nombre de archivo como antes. Estas funciones deben llamar a open() en el nombre de archivo proporcionado y usar las nuevas funciones csv_as_dicts() o csv_as_instances() en el archivo resultante.

(c) Desafío de diseño: encabezados CSV

El código supone que la primera línea de datos CSV siempre contiene encabezados de columna. Sin embargo, este no siempre es el caso. Por ejemplo, el archivo Data/portfolio_noheader.csv contiene datos, pero no encabezados de columna.

¿Cómo refactorizarías el código para acomodar los encabezados de columna faltantes, haciendo que el llamador los proporcione manualmente?

(d) Desafío de API: sugerencias de tipo

Las funciones pueden tener sugerencias de tipo opcionales adjuntas a los argumentos y valores de retorno. Por ejemplo:

def add(x:int, y:int) -> int:
    return x + y

El módulo typing tiene clases adicionales para expresar tipos más complejos, incluidos los contenedores. Por ejemplo:

from typing import List

def sum_squares(nums: List[int]) -> int:
    total = 0
    for n in nums:
        total += n*n
    return total

Tu desafío: modifica el código en reader.py para que todas las funciones tengan sugerencias de tipo. Intenta que las sugerencias de tipo sean lo más precisas posible. Para ello, es posible que tengas que consultar la documentación del módulo typing.
